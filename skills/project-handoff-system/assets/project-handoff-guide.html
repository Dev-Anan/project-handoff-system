One shared workflow · Any coding agent

ให้งานเดินต่อได้ แม้เปลี่ยน session

Project Handoff ช่วยเก็บงานที่กำลังทำ การตัดสินใจ จุดตรวจ และขั้นถัดไปไว้กับ Git repository เพื่อให้คนหรือ agent อีกตัวกลับมาทำต่อได้จากข้อมูลจริง

Git-backedเลือกติดตั้งเป็น skillปรับได้ตามโปรเจกต์

แนวคิดหลัก

เก็บบริบทการทำงานในไฟล์ที่ตรวจสอบได้ ไม่ฝากสถานะไว้กับบทสนทนาหรือ agent ตัวใดตัวหนึ่ง

01 / TASK

ระบุขอบเขตและผู้รับผิดชอบ

แต่ละ task บันทึกเป้าหมาย สถานะ acceptance และผู้ทำงานไว้ใน repo

02 / CHECKPOINT

จดจุดที่กลับมาทำต่อได้

เก็บ revision, ไฟล์ที่เปลี่ยน blocker และ next action แบบเฉพาะเจาะจง

03 / EVIDENCE

อ้างผลตรวจที่เกิดขึ้นจริง

เชื่อมผล validation กับ task เพื่อให้การส่งต่องานมีบริบทตรวจสอบได้

04 / HANDOFF

ใช้ร่วมกันข้าม agent

กติกาและข้อมูลอยู่ใน repository; agent ที่เข้ามาใหม่อ่านจากแหล่งเดียวกัน

ติดตั้ง skill

ใช้ Skills CLI เพื่อเลือก agent และตำแหน่งติดตั้ง หรือเลือกติดตั้งเฉพาะ agent ที่ใช้จริง

npx skills@latest add Dev-Anan/project-handoff-system
  1. เลือก skill ชื่อ project-handoff-system
  2. เลือก coding agent และระดับการติดตั้งตามที่ต้องการ
  3. เปิด repository เป้าหมายใน agent นั้น
  4. ขอให้ agent ใช้ skill เพื่อตรวจและตั้งค่า repository

ตัวอย่างคำขอ: Use the project-handoff-system skill to inspect and set up this repository.

ตั้งค่า repository เป้าหมาย

เริ่มด้วยการตรวจบริบทเดิมก่อนสร้างไฟล์ เพื่อคง tracker และกติกาที่โปรเจกต์ใช้อยู่

inspect→dry run→review→install→adapt
node <skill-dir>/scripts/install.mjs --target /absolute/path/to/repository --dry-run
node <skill-dir>/scripts/install.mjs --target /absolute/path/to/repository

ตัวติดตั้งจะหยุดเมื่อพบ tracker หรือไฟล์ชนที่ต้องตัดสินใจ ให้ map ระบบเดิมและเลือกแหล่งสถานะหลักก่อนติดตั้ง เพื่อไม่ให้มี task database ซ้ำกัน

เริ่มและส่งต่องาน

คำสั่งที่ติดตั้งมาช่วยอ่านงานปัจจุบัน สรุป task และตรวจความครบถ้วนของไฟล์

npm run project:resume
npm run project:status
npm run project:check
  1. ก่อนแก้ไข ให้เทียบ task checkpoint กับ branch, revision และ working tree จริง
  2. ระบุผู้ทำงาน, session, base revision และ next action ใน task
  3. หลังความคืบหน้าสำคัญ บันทึก checkpoint พร้อมไฟล์ที่เปลี่ยน
  4. ก่อนส่งต่อ เขียน session record แนบ validation ที่รันจริง และตรวจความสอดคล้อง

โครงสร้างข้อมูล

ตำแหน่งหน้าที่
AGENTS.mdทางเข้าและข้อกำหนดเฉพาะของ repository
docs/work/tasks/task records เป็นเจ้าของสถานะและ acceptance
docs/work/current.jsonชี้ task ที่เลือก; ไม่เก็บสถานะซ้ำ
docs/work/sessions/บันทึกความคืบหน้า ผลตรวจ และขั้นถัดไป
scripts/project-workflow.mjsคำสั่ง resume, status และ check

สถานะ task ใช้สื่อความจริง เช่น BACKLOG ยังไม่ใช่การอนุมัติเริ่มงาน และ DONE ต้องมี acceptance กับหลักฐานครบ การ release บันทึกแยกต่างหาก

ปรับให้เข้ากับแต่ละโปรเจกต์

workflow เป็นโครงกลาง ส่วนคำสั่ง โครงสร้าง source และข้อกำหนดของงานให้ยึดตาม repository ปลายทาง

  • ใส่คำสั่งตรวจที่โปรเจกต์ใช้อยู่จริง ไม่เพิ่มขั้นตอนสมมติ
  • เชื่อมเอกสารสถาปัตยกรรมและรูปแบบโค้ดที่เกี่ยวกับงาน
  • รักษา instructions และ configuration เดิมของแต่ละ agent
  • ถ้ามีหลาย agent ทำพร้อมกัน ให้แยกผู้รับผิดชอบและ Git worktree ให้ชัด

ตัวตรวจเช็กความครบถ้วนของโครงสร้างและลิงก์ได้ แต่ไม่สามารถยืนยันแทนคนได้ว่าหลักฐานเป็นจริงหรือมีการอนุมัติแล้ว
