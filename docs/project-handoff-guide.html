ติดตั้งใน repo เป้าหมาย

ให้ Codex ใช้สกิล $project-handoff-system พร้อมระบุ path ของ repo หรือรันตัวติดตั้งจากสกิลนี้โดยตรง ตัวติดตั้งจะตรวจไฟล์ชนก่อนเขียนและเริ่มต้นด้วย task registry ว่าง

node ~/.codex/skills/project-handoff-system/scripts/install.mjs --target /absolute/path/to/repo --dry-run
node ~/.codex/skills/project-handoff-system/scripts/install.mjs --target /absolute/path/to/repo
  1. ดูรายการไฟล์ใน dry run และตรวจว่า repo มีระบบงานเดิมหรือไม่
  2. รันคำสั่งติดตั้งจริง
  3. เปิด Git diff แล้วปรับหัวข้อที่เพิ่มใน AGENTS.md ให้ตรงกับกติกาของโปรเจกต์
  4. รันคำสั่งตรวจด้านล่าง

หากมี docs/work/ หรือ package script ชื่อเดียวกันอยู่แล้ว ตัวติดตั้งจะหยุดก่อนเขียน ให้ใช้สกิลช่วย map ระบบเดิมและกำหนดแหล่งข้อมูลหลัก ไม่สร้าง tracker ซ้ำโดยเงียบ ๆ

สิ่งที่ตัวติดตั้งสร้าง

ไฟล์หน้าที่
AGENTS.mdเพิ่มกติกาเริ่ม session และขอบเขตการทำงาน โดยเก็บข้อความเดิมไว้
docs/work/current.jsonชี้ task ที่เลือกหรือ null
docs/work/tasks/เก็บ task JSON แต่ละรายการเป็นเจ้าของสถานะของตน
docs/work/templates/ต้นแบบ task และ session record
docs/work/README.mdกติกาสถานะ การรับงาน และหลักฐาน
scripts/project-workflow.mjsคำสั่งอ่านสถานะและตรวจความสอดคล้อง
docs/project-handoff-guide.htmlคู่มือนี้ ใช้สอนคน ไม่เก็บสถานะสด

ตัวติดตั้งเพิ่ม npm scripts ใน package.json และสร้างตัวชี้จาก CLAUDE.md/GEMINI.md เมื่อยังไม่มีไฟล์เหล่านั้น

ลำดับงานในแต่ละวัน

resume→ตรวจ Git→claim→ทำงาน→checkpoint→check
npm run project:resume  # งานที่เลือก + checkpoint + Git จริง
npm run project:status  # รายการงานจาก task files
npm run project:check   # ตรวจโครงสร้างและลิงก์หลักฐาน

เมื่อไม่มี task ที่เลือก ให้ใช้คำขอของผู้ใช้เป็นตัวกำหนดงานใหม่ เมื่อมี task ที่อนุมัติแล้ว ให้ระบุ executor, session, branch, base commit และ next action ก่อนแก้ source หลังทำขั้นสำคัญให้เขียน checkpoint ทันที

ก่อนจบ session

  • บันทึกสิ่งที่ทำ ไฟล์ที่เปลี่ยน และ Git revision จริง
  • ระบุผล validation ตามคำสั่งที่รันจริง พร้อมไฟล์หลักฐาน
  • ระบุ blocker และขั้นถัดไปแบบลงมือได้
  • รัน project:check หลังอัปเดต task/session

ใช้สถานะให้ตรงความจริง

สถานะใช้เมื่อ
BACKLOGบันทึกไว้พิจารณา ยังไม่อนุญาตให้เริ่ม
READYอนุมัติขอบเขตและ dependency พร้อม
IN_PROGRESSexecutor รับงานและกำลังทำ
VERIFYงานมีแล้ว แต่ยังขาดผลตรวจหรือการยืนยัน acceptance
BLOCKEDต้องรอคำตอบหรือสถานะภายนอกที่ทำต่อไม่ได้
PAUSEDหยุดชั่วคราวพร้อม checkpoint กลับมาทำต่อได้
DONEacceptance ทุกข้อ PASS มีหลักฐานแล้ว

สถานะ release อยู่ต่างหาก งาน DONE ไม่ได้แปลว่า deploy แล้ว และไม่อนุญาตให้เปลี่ยนราคา สิทธิ์ หรือบริการภายนอกเอง

ปรับให้เข้ากับโปรเจกต์อื่น

เริ่มจากชื่อคำสั่ง, โครงสร้าง source, วิธีทดสอบ, ผู้ตัดสิน acceptance และลิงก์เอกสารที่ repo มีจริง เติมรายละเอียดเฉพาะโปรเจกต์ใน AGENTS.md หรือเอกสารอ่านตามความจำเป็น อย่ายก Firebase rules, backlog, Graphify output หรือข้อกำหนดธุรกิจของ Car-eService ไปใช้

  • Node / Python / Go / Rust
  • เว็บ / โมบาย / backend
  • repo เดี่ยว / monorepo

ตัว CLI ต้องใช้ Node.js และ Git แม้ตัวแอปจะเขียนภาษาอื่น หาก repo มี task tracker เดิม ให้กำหนดว่าไฟล์ใดเป็นแหล่งสถานะหลักก่อนติดตั้ง หากหลาย agent ต้องทำพร้อมกัน ให้แยก owner หรือ worktree เพราะ validator นี้ไม่ใช่ lock

npm run project:resume
